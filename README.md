# code-basics

A lightweight desktop IDE companion: run projects, run tests, and work with git across .NET and JavaScript/TypeScript workspaces — without a full IDE.

Built as a native desktop application (Tauri 2): a compiled Rust core does all the real work, and the interface renders in a native window. There is no web server and nothing is hosted; `pnpm tauri build` produces a regular Windows executable and installers.

## What it does

- **Run** — discovers runnable projects, `launchSettings.json` profiles, and `package.json` scripts; launches them with streamed output in per-run console tabs, and kills the whole process tree on cancel. Configurations live in a toolbar dropdown (status dots, favourites, custom ordering) — one entry per project, not one per build flag: **Debug/Release** is its own picker beside the `ASPNETCORE_ENVIRONMENT` one, remembered per configuration and applied to builds as well as runs, so a project appears once rather than three times. **Stop** is a split button: its main half stops the selected configuration and its caret lists only configurations launched with Run, across codebases, with terminals and unrelated background work kept out. Beside Run is **Debug**, which launches .NET and Node applications under a real debug adapter, so behaviour that depends on a debugger being attached is active. The application's own output streams into the same console tab, and keeps streaming for applications that log heavily — a debug adapter emits output far faster than a UI can draw it, and a client that falls behind does not merely lag: it suspends the application it is debugging. Both adapters — [NetCoreDbg](https://github.com/Samsung/netcoredbg) and the standalone [js-debug](https://github.com/microsoft/vscode-js-debug) server, both MIT — **ship with the installer**, so a fresh install debugs with nothing else to download; a missing one is always explained rather than quietly downgraded to an ordinary run. Build/rebuild/clean actions and a **Secrets…** control that opens a .NET project's user secrets as an ordinary editor tab — including a `UserSecretsId` inherited through MSBuild — round out the tab.
- **Edit** — a directory tree of the workspace sits beside the Run tab's console; **right-click the tree** to add a file or folder, rename, or delete (a new file opens straight away, and deleting closes the tabs beneath it so a pending save cannot recreate it); files open in a syntax-highlighted CodeMirror editor above it (Ctrl+S saves, Ctrl+F finds within the file, Ctrl+/ toggles comments, the split is resizable, and the console collapses to a strip when you want the screen for code — closing the last file expands it again, since with no editor above it that pane is the whole view), covering the quick fix-and-rerun loop without switching tools.
- **Trace a method** — an inline row above every declaration says how many places use it, and drops down the list; clicking one opens that file at that line. Middle-click a symbol to go to its definition, with a grouped picker when there is more than one place to go. The answers come from real [language servers](docs/guides/language-servers.md) already on your machine (Roslyn for C#, `rust-analyzer`, `typescript-language-server`, a Python server) — nothing is bundled, and a count is never guessed: while a server is still loading, or when none is installed, the row says so instead of showing a number.
- **Tests** — discovers test projects (VSTest, Microsoft.Testing.Platform, Vitest, Jest — plus anything added via a [declarative adapter](docs/guides/adding-an-ecosystem.md)), runs them with live output and live per-test progress, parses the report into a project → suite → test tree, and can re-run only the failures.
- **Changes** — git working-copy review with side-by-side or inline diffs, staging, unstaging, and revert down to the individual line, plus commit operations. A **Files / Intent / Stashes / Erosion** toggle switches the list between the file list — as a **collapsible folder tree by default**, or a flat list of full paths if you prefer, with folds remembered per repository — the [decisions behind the diff](docs/guides/agent-intent-capture.md) (captured from a coding agent as it works — where each card and file also shows whether it is staged, and where a reason is retired once your commits absorb it, so finished work stops labelling new changes; **right-click a card or one of its files to move those changes into another card or a new one** when the automatic grouping gets it wrong), a full **stash manager** (named stashes with a per-stash diff preview and apply / pop / drop / clear — and, from the file list, **right-click one or more selected files to stash just those**, leaving every other change in the working tree), and an **erosion scan** — a rules-based, no-model pass that flags the changes quietly weakening the codebase (deleted assertions, skipped tests, widened catches, introduced panics, stubs left in production paths, removed safeguards or logs), each flag clicking through to its diff line and extensible with your own regex rules in `.code-basics/erosion/`. A change you disagree with can be **rejected**: reverted with your reason left in the code for the agent to fix, and a `pre-commit` hook that refuses to commit until it has been. The Intent grouping also offers **before/after evidence**: **Run before/after** builds the change against both `HEAD` (in an isolated git worktree) and the working tree, runs the same tests and captures the same console output — and, when a `.http` scenario and a server launch are present, replays the requests against both — then diffs the observable outcomes and attaches each difference to the card that plausibly caused it. Each difference expands to the evidence behind it — the console lines that appeared and disappeared, an HTTP response's status, headers and body, which test cases moved — and anything it could not attribute says why. It is evidence a change did what was claimed without reading it; every threshold abstains rather than guess.
- **History** — commit log with per-commit diffs, a branch folder tree (slash-named branches group into folders, with multi-select bulk delete), and push/pull/fetch.
- **Branches everywhere** — a Rider-style titlebar widget with a branch tree (slash-named branches group into folders), switching (including remote checkout), creation from any base, and fetch/pull/push.
- **Rider import** — converts JetBrains Rider `.run/*.xml` configurations, with a review step that surfaces anything that could not be translated.
- **[Enhancements](docs/guides/instruction-enhancements.md)** — a menu bar with a File menu and an Enhancements menu driven by plain `.md` files you drop in a folder: **Add Instructions** adds a reusable, marker-bounded section to the workspace's `CLAUDE.md`/`AGENTS.md` (idempotent, backed up, confirmed first), and **Run Agent** runs a saved prompt as an agent (read-only or edit), with `once: true` prompts recorded per repo.
- **Terminals** — floating, interactive terminal windows you can open anytime (drag, resize, minimize to a pill that flashes when a hidden session rings the terminal bell — and the codebase's tab pulses amber when the terminal belongs to a background project, or twice in green when one simply finishes). Each is a real pseudo-terminal running your shell, so you can launch Claude Code — or anything — and interact with it live; copy and paste with the usual chords (Ctrl+Shift+C / Ctrl+V). Several can run at once and they survive tab switches; clicking one brings it to the front (anywhere on it, not just the header), while the Notes panel stays above them all. Closing one ends its whole process tree.
- **Launch other apps** — a titlebar **Launch** button runs any command line, not just a detected project: a local Redis, `docker compose up`, a Python script, ngrok. Running a command is what remembers it — the picker lists what you have run before, this codebase first, each pinnable, renamable and forgettable, and the list is stored globally so your usual tools are there in every project. Launched apps run in the background with no console window of their own; their output goes to one floating **Apps** panel with a tab per app (the same console as the Run tab — search, copy diagnostics, and a **severity picker** that narrows the tab to *Info+*, *Warn+* or *Errors* — and the tab stays after the app exits, showing its exit code). Everything launched appears in the **Running** panel with its pid and age, where **View** jumps to its output and **Kill** stops it; a launched app is not tied to the codebase you started it from, so switching or closing that tab leaves it running. Shell syntax (`|`, `>`, `&&`) needs the "run through shell" box, and is refused rather than silently mangled without it.
- **Notes** — a floating, resizable scratchpad for free-form notes and prompts-for-later, with several named, individually colored tabs in one panel (add, rename, delete) and minimize to a thin labeled bar; clicking the titlebar Notes button restores a minimized panel. Edits autosave and survive an app crash or restart without an explicit save. Notes are stored globally (in your user config directory, not per-workspace), so the same scratchpad is available in every project. Any note can be **sent to an agent** (run as a prompt in the agent panel) or **saved as an instruction** so it joins the Enhancements → Add Instructions library.
- **Customize the app** — **File → Settings** controls UI and code fonts independently, scales their font sizes, and edits a complete colour theme spanning the chrome, editor syntax, diffs and terminals. Start from the built-in Dark or Light theme, duplicate one into an editable custom theme, and import/export themes as JSON. The searchable keyboard page shows every app command and its current one-chord shortcut, detects conflicts, and resets commands individually or together; native editor and terminal keys are listed separately as a read-only reference.
- **Multiple codebases at once** — open several projects as tabs above the view row and switch between them instantly. Each keeps its own runs, tests, terminals and language server alive in the background, so switching interrupts nothing; the active codebase's folder, path and branch show in the app chrome, and a background codebase **signals on its tab** what happened in it: failures stay red until viewed, a terminal bell stays amber until acknowledged, and successful builds, tests, terminals or launched apps flash green briefly. Cancelling is quiet, and the louder signal always wins, so a later success never hides a failure.
- **Console built for troubleshooting** — clickable URLs, severity colouring, Ctrl+F search, filtering by severity/text, copy-on-select, and a one-click paste-ready diagnostics block. A line is ranked by the level marker the program wrote (`fail:`, `warn:`, `error CS1234:`); only a line with no marker at all falls back to the stream it came from, where `stderr` counts as an error, and indented lines inherit the line above so filtering to errors keeps a stack trace with its failure.

## Quick start

Prerequisites: [Rust](https://rustup.rs) (stable, MSVC toolchain on Windows), the Visual Studio C++ Build Tools, [Node.js](https://nodejs.org) and [pnpm](https://pnpm.io). Details in [Installation](docs/getting-started/installation.md).

```sh
pnpm install
pnpm tauri dev          # run the app (first build takes several minutes)
pnpm sidecar:build      # optional: the .NET object inspector (needs the .NET SDK)
pnpm tauri build        # produce a distributable executable + installers
```

Open a workspace from the welcome screen, or pass it on the command line: `code-basics <path>`.

## Repository layout

```
crates/core/     cb-core: all logic (detection, adapters, test parsing, git, processes) — no Tauri dependency
src-tauri/       the Tauri shell: state, adapter dispatch, IPC command surface
src/             React frontend: six tab views, CodeMirror diff/editor components, typed IPC wrappers
docs/            documentation (see docs/README.md)
scripts/         docs/index maintenance scripts
examples/        worked declarative adapter manifests (pytest, cargo-nextest)
```
